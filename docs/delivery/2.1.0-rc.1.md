Historical September results are background evidence; the runs below exercise the candidate
source. Full command output and result bundles are retained in `build/rc-2.1.0-rc.1/`.

Real installed Whisper and Qwen inference cases passed, including shared file/dictation
scheduling, language preservation and Casual word preservation. Skips include opt-in renders,
physical microphone/Accessibility/History interactions, Keychain/Secure Enclave and an optional
external noise fixture; they are not counted as manual acceptance. No model was downloaded.

The initial native run also passed but exposed stale Xcode first-launch components. After
`xcodebuild -runFirstLaunch` installed the matching components, the full native run passed again.
Xcode 27.1 still emits its own `IDELaunchSession` completion-handler advisory. The repository's
text warning check and structured xcresult diagnostics report no warnings; the final PR CI on
Xcode 26 is an independent gate. This records the toolchain diagnostic rather than suppressing it.

Commands used (from the repository root):

```sh
python3 -m unittest discover -s scripts/tests -v
TEST_RUNNER_VOXFLOW_MCP_INTEGRATION=1 xcodebuild -xcconfig Build.xcconfig -scheme VoxFlow \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath build/local-debug \
  -parallel-testing-enabled NO build test \
  -resultBundlePath build/rc-2.1.0-rc.1/native-final.xcresult
xcrun xcresulttool get object --legacy --path build/rc-2.1.0-rc.1/native-final.xcresult \
  --format json > build/rc-2.1.0-rc.1/native-final.json
swift test --package-path VoxFlowKit
python3 scripts/check_build_logs.py build/rc-2.1.0-rc.1/native-final.log \
  build/rc-2.1.0-rc.1/package.log --xcresult-json build/rc-2.1.0-rc.1/native-final.json
bash scripts/install.sh --build-only
```

Build/test commands above had complete stdout/stderr redirected to their named log files.

## Promotion and local use

The promotion PR targets `master`. Merge only after its final CI is green, using a merge commit
to preserve the `develop` ancestry. The exact candidate source is the PR head commit; any
subsequent source change needs appropriate validation. Preparing this PR neither merges it nor
creates a stable release. After authorized promotion, tag the reviewed source as `v2.1.0-rc.1`
and merge release changes back into `develop`. Do not use the stable `v2.1.0` tag for this RC.

Build and verify locally with `bash scripts/install.sh --build-only`. To install, quit VoxFlow
and use `bash scripts/install.sh`, then launch `/Applications/VoxFlow.app`. Preserve the existing
signing identity. See the [release process](release-process.md) for signature and rollback checks.
Release preparation does not require replacing the owner's running installation.

Developer ID signing, notarization, DMG/public GitHub Release assets and auto-updates are outside
this local candidate's scope. Public distribution needs a separate validated delivery process.
